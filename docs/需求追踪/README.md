# 需求追踪文档的使用规则

`docs/需求追踪/` 是**历史决策库**：记录某个需求当时为什么这样做、验证了什么、
留下了哪些风险。它不是当前架构文档，也不是每次改代码都必须读的入口。

## Agent 读取顺序

1. 先读 [`docs/subsystems/`](../subsystems/README.md) 的当前状态；
2. 再按关键词搜索本目录，只读与当前任务相关的那几份；
3. 如果历史文档与当前代码冲突，以代码和 `docs/subsystems/` 为准，并在 PR 里说明冲突。

## 新文档要求

新建 `需求进度追踪-*.md` 时，开头必须写：

```md
- 状态：active / shipped / abandoned / superseded
- 提出日期：YYYY-MM-DD
- 关联 issue/PR：
- 当前代码入口：
- 验证命令：
```

已完成的文档不要删除；把状态改成 `shipped`，并补上最终落地的代码/测试链接。
被后续方案替代的，标 `superseded` 并链接新文档。

## 维护规则

- 一份文档只记一个需求；不要把多个需求揉在一起。
- 方案变更时更新同一份文档，不另开一份“最终版/真的最终版”。
- 未确认的结论标“未确认”，不要写成事实。
- 文档不替代测试；行为以代码、测试和 `docs/subsystems/` 为准。
