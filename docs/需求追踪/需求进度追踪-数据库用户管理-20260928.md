# 需求进度追踪 - 数据库用户管理

## 1. 需求摘要
- 需求名称：数据库用户管理（账号 / 角色 / 权限）
- 提出日期：2026-09-28
- 负责人：Claude Code
- 目标：参照 Navicat「用户管理」，在标题栏「SQL 工具」右侧提供跨数据源的账号、角色与权限管理，覆盖同一数据源不同版本的差异（如 MySQL 5.x/8.x 默认认证插件、PG 14+ scram-sha-256、Oracle CDB/PDB、Redis <6 无 ACL）
- 非目标：批量多账号操作；Oracle PROFILE / 达梦策略对象本身的增删改；LDAP/Kerberos 服务端配置；登录历史审计；通过 MCP/AI 调用用户管理

## 2. 范围与验收
- 范围：
  - 完整支持：MySQL（5.5–9.x）、MariaDB、GoldenDB、OceanBase（MySQL 模式 / Oracle 模式）、PostgreSQL（9.4–17）、人大金仓、瀚高、openGauss、GaussDB、Vastbase、SQL Server（2005–2022 + Azure SQL）、Oracle（11g–23ai，含 CDB/PDB）、达梦、ClickHouse（20.4+）、TDengine（2.x/3.x）、MongoDB（3.6–8.x）、Redis（6.0+ ACL，单机/集群/哨兵）
  - 不支持：SQLite、DuckDB、Sphinx、Trino、自定义连接、IRIS/Caché、Doris/StarRocks、IoTDB、Elasticsearch、向量库、消息队列、Nacos、JVM
- 验收标准：
  - 标题栏「SQL 工具」右侧出现「用户管理」按钮；连接右键菜单出现「用户管理」（仅支持的数据源）
  - 以工作台标签页打开，每个连接一个标签；无可用连接时展示连接选择器
  - 列表、详情、新建、改密、锁定、改名、授权/撤权、角色成员、默认角色、删除（含影响分析）、导出账号脚本
  - 所有写操作先预览（口令掩码），Apply 由后端按同一结构化请求重新生成计划并校验指纹
  - 「限制结构修改」保护下只读；生产环境一律倒计时确认；自锁 / 保留账户强提示
  - 口令不出现在预览、审计、日志、错误文本中
- 依赖与约束：外置驱动 agent 只转发固定方法，因此所有语句由 `internal/dbuser` 生成并经 `db.Database` Query/Exec 下发

- 风险：

- 阻塞：无
- 缓解措施：版本号 + 运行时探测双保险；探测失败降级而非报错；契约 JSON 可一键关闭入口

## 6. 决策记录
- 决策 1：Apply 不接受前端 SQL，后端按同一 ChangeRequest 重新 Probe + Plan，指纹不一致拒绝执行
- 决策 2：不复用 `quoteIdentByType` / `escapeSQLStringLiteralBody`（去引号语义与不感知 NO_BACKSLASH_ESCAPES 会导致口令写错），在 `dbuser/quote.go` 实现「始终加引号」规则
- 决策 3：原生 PG 10+ 客户端预计算 SCRAM-SHA-256 verifier（RFC 7677 向量校验），明文不进服务端日志；国产 PG 分支走服务端哈希
- 决策 4：生产确认对用户管理使用更严规则（生产环境即倒计时，不因其他保护项跳过）
- 决策 5：Redis 不扩展连接保护开关，写操作一律生产倒计时 + 显式确认
- 决策 6：MCP Backend 不暴露任何 `UserMgmt*` 方法（反射守卫测试）
